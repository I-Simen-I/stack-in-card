# Stack In Card

A Home Assistant dashboard card (TypeScript, webpack, no Lit), distributed as
one file, `dist/stack-in-card.js`, through the Marketplace/HACS. It wraps a
`vertical-stack` or `horizontal-stack` in one `ha-card` and strips the
background, border, border-radius, box-shadow and spacing of the cards inside,
so they look like one card. Fork of custom-cards/stack-in-card (RomRider),
whose last release was 0.2.0 in 2020. Code, commits, PRs, README and release
notes are in English.

The reference for tooling, tests, CI, docs and workflow is
[I-Simen-I/simple-weather-card](https://github.com/I-Simen-I/simple-weather-card). Keep the two in
step: copy its setup instead of inventing a new one. Deviations on purpose
are listed under Decisions.

Personal, machine-specific notes go in `.claude/rules/personal.md` (not
committed; every file in `.claude/rules/` is loaded automatically).

## Maintainer

Claude is the main maintainer of this code. The repository owner decides
what the card should do, tests it in Home Assistant and releases it; the
code itself is Claude's responsibility. Work like an owner:

- Read the code around a change before writing any. Reuse what's there
  (`loadCardHelpers` in `src/card-helpers.ts`, the helpers in
  `test/helpers.mjs`, Home Assistant's own elements and translations)
  instead of writing a second version. If something almost fits, change it
  so it fits both uses.
- Prefer less code: no options, abstractions or fallbacks the card doesn't
  need. Small functions with names that say what they do; comments for why,
  not what.
- Leave the code better than you found it. When a change makes code,
  options, tests or docs obsolete, remove them in the same change.
- Keep the code, tests, README, `dev/` and this file in step: a change
  isn't done until all of them match it.
- Say so when a request would make the code worse, and suggest a better
  way, before building it.

## Layout

- `src/stack-in-card.ts` – the card. `src/editor.ts` – visual editor,
  imported by the card into the same bundle. `src/card-helpers.ts` – loads
  `window.loadCardHelpers()` once. `src/types.ts` – config and the few Home
  Assistant types it uses. `src/declarations.d.ts` – `__VERSION__`.
- No translation files: the editor's three labels come from Home
  Assistant's own translations (`hass.localize`), see `LABELS` in
  `src/editor.ts`.
- `test/` – Node test runner. `card.test.mjs` and `editor.test.mjs` load
  the **built** bundle in happy-dom, with fake `hui-*-stack-card`,
  `hui-card`, `test-card` and `hui-stack-card-editor` elements from
  `helpers.mjs` shaped like Home Assistant's, so `yarn build` before
  `yarn test`. `next-version.test.mjs` tests the release script.
- `.github/workflows/` – build (typecheck, lint, formatting, build, test,
  artifact), release (manual button), labeler, HACS validation.
- `dev/` – local Home Assistant in Docker for manual testing.
- `images/` – README images, taken from the test dashboard (see
  `dev/README.md`): `main.png` (top: the card next to HA's vertical
  stack, Compare view) and `demo_1.png`–`demo_3.png` (one per example,
  Gallery and Basics views). The README's examples show the same cards as the views;
  change both together. `editor.png` (the editor, from the Compare view) is in the README's Visual
  editor section, as in simple-weather-card.

## Workflow

- Never commit on `master`; create a branch first. The prefix sets the PR
  label and release notes category: `feat/` (Features), `fix/` (Fixes),
  `chore/`, `ci/`, `docs/`, `refactor/` (Maintenance).
- Commit when a piece of work is done and verified. Messages: short subject,
  blank line, bullets with the why.
- Run `yarn prettier --write` on every file before committing it, also
  JSON, YAML and markdown, and files from others or generated by scripts.
- Wait for the checks before merging: deleting the branch right after
  merging makes the PR's HACS validation fail with "Not Found".
- Releases: Actions → Release → Run workflow (patch/minor/major, beta). It
  creates a draft with generated notes; a summary goes above them before
  publishing. Tags are `vX.Y.Z`; upstream's tags (`0.2.0`, no `v`) aren't in
  the fork. The first release is v1.0.0: with no tags, a **major** bump
  gives `v1.0.0` (patch or minor would give `v0.0.1`/`v0.1.0`).
- Verify claims instead of guessing (Home Assistant's frontend source, git
  history, the GitHub API). Before saying something works, test it, and say
  clearly what wasn't tested.
- New behavior gets smoke tests that fail against `master`.
- The release workflow builds with `CARD_VERSION=<tag>` before the smoke
  tests, so tests must pass with a tag too (`CARD_VERSION=v1.0.0 yarn build
&& yarn test`), not only with the local `dev`.
- happy-dom resolves `customElements.whenDefined()` with `undefined`; look the
  class up with `customElements.get()`. It normalizes inline styles
  (`borderRadius = "0"` reads back as `"0px"`).

## How the card works

- `setConfig` requires a `cards` list and a `vertical`/`horizontal` `mode`.
  It creates a `${mode}-stack` with `window.loadCardHelpers()`
  (`createCardElement`). `hass` and `preview` are passed to the stack when it
  is ready and on every change after that.
- The stack sits in a `.stack` wrapper that sets HA's CSS variables
  (`--ha-card-background`, `--ha-card-border-width`,
  `--ha-card-border-radius`, `--ha-card-box-shadow`, and the stack and grid
  gaps) to nothing, so cards that use them are merged from their first
  paint. Don't rely on the DOM walk alone: `ha-card` has
  `transition: all 0.3s`, so styles set after render show the borders
  fading out on every page load.
- As a fallback for cards with their own styles, the card also walks the
  DOM when a stack is shown (`_styleTree`), and again after 500 ms for
  cards that render late: in a shadow root it merges the
  `ha-card`, or, in stacks, goes through the `#root` (or `#card`) container
  and its children; in the light DOM (`hui-card`) it goes through the
  children. Inline styles: `background`, `border`, `border-radius`,
  `box-shadow` on every `ha-card`, `margin` on the children, `gap` on stack
  roots.
- A nested `stack-in-card` gets its `ha-card` merged like any card, and
  merges its own cards.
- Cards inside are created and rendered by Home Assistant as usual, with
  their own Lit if they have it. Cards that style their own `ha-card`
  without HA's variables (simple-weather-card's `backdrop`, a colored
  button-card) are only merged by the DOM walk, just after they render,
  and lose their own background color: that's by design.
- `ll-rebuild` from the stack recreates it.
- Visual editor: a `mode` form on top, then Home Assistant's own stack
  editor (`hui-stack-card-editor`, from
  `customElements.get("hui-vertical-stack-card").getConfigElement()`) for
  the title and the cards. The stack editor validates with superstruct and
  rejects unknown options, so it only gets
  `{ type: "<mode>-stack", title, cards }`; its `config-changed` is stopped
  and merged into the full config. The mode field is labelled with HA's
  "Layout" (`ui.panel.lovelace.editor.edit_view.type`; "Oppsett" in nb) and
  the stack names (`card.vertical-stack.name`, `card.horizontal-stack.name`),
  with English fallbacks. They are in HA's `lovelace` translation fragment,
  which can load after the editor, so the schema is rebuilt when
  `hass.localize` changes. `mode` is only stored when horizontal;
  `keep` from the original card is removed on any change.
- Card picker: `preview: true` in `window.customCards`, and
  `getStubConfig(hass, entities, entitiesFallback)` returns a
  `weather-forecast` card above a `horizontal-stack` of three buttons, with
  the entities the picker suggests first (like HA's own cards). No weather
  entity: no weather card. Too few lights/switches: icon-only buttons. It's
  also the config a new card starts with.

## Decisions

- Everything always merges: no options to keep the background, border,
  rounded corners, shadow or spacing of the cards inside (the original
  card's `keep` and `--keep-background`/`--keep-border` were removed on
  purpose, 2026-11-25). `keep` in old configs is ignored, not an error.
  The merge styles are set inline without `!important` on purpose, so
  card-mod with `!important` on a card inside can still override them;
  that's an accepted escape hatch.
- No Lit or other runtime dependencies: the card and editor are plain
  custom elements (2026-11-26). They only render one `ha-card` and one
  `ha-form`; Lit was ~70% of the bundle (24 KB → 6 KB). simple-weather-card
  uses Lit because it renders far more. Add a dependency only when it saves
  more than it costs.
- No translation files of our own: the editor uses Home Assistant's
  translations, which cover every language. Add own translations only if
  the editor gets text HA has no string for.

## Home Assistant specifics

Check against the reference implementation before inventing something: HA's
frontend repo (`home-assistant/frontend`), especially
`src/panels/lovelace/cards/hui-stack-card.ts`,
`hui-vertical-stack-card.ts`, `hui-horizontal-stack-card.ts` and
`hui-card.ts`.

- Stacks render `<div id="root">` in their shadow root, with every card
  wrapped in a `hui-card`, which renders the card in its light DOM. Since
  2024.3 the cards are spaced with `gap` on `#root`
  (`--vertical-stack-card-gap`, `--horizontal-stack-card-gap`,
  `--stack-card-gap`, default 8px), not margins.
- `ha-card` has a border since 2022.11 (`--ha-card-border-width`, 1px).
  Its look comes from `--ha-card-background`, `--ha-card-border-width`,
  `--ha-card-border-color`, `--ha-card-border-radius`,
  `--ha-card-box-shadow` and `--ha-card-backdrop-filter`
  (`src/components/ha-card.ts`), with `transition: all 0.3s ease-out`.
- The card depends on this internal DOM. Changes in Home Assistant's frontend
  can break it without any change here; check the test environment against a
  new Home Assistant version when something looks off.
- From HA 2026.11, HACS is built in as the **Marketplace** (still reads
  `hacs.json`, category `plugin`). The card supports HA 2026.4+, so docs
  mention both.

## Test environment (dev/)

- HA at http://localhost:8124 (8124, so simple-weather-card's can run on
  8123), login skipped from localhost. Compose project `stack-in-card`,
  container `stack-in-card-ha`; both forks have `dev/docker-compose.yml`, so
  without the `name:` the projects clash and one replaces the other's
  container.
- Dashboard "Stack in card" (`dev/config/dashboards/stack.yaml`): Compare
  and Gallery (the README images, see `dev/README.md`), Basics (both modes next to HA's
  own stacks with the same cards) and Nested.
- The demo has only outdoor sensors; `configuration.yaml` adds template
  sensors `sensor.indoor_temperature` and `sensor.indoor_humidity` (fixed
  values) for the living room card.
- `dev-loader.js` imports the card with `?t=<now>`, because HA serves
  `/local/` with a 31 day cache. Other files in `www/` need a hard refresh.
- Changes to `configuration.yaml` need `docker restart stack-in-card-ha`.
  Check config with
  `docker exec stack-in-card-ha python3 -m homeassistant --script check_config -c /config`.
